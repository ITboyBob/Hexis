# BOB-108 前后台工具 Activity 展示需求与设计

日期：2026-10-09。状态：需求范围已确认，实施设计与执行计划待审阅；产品尚未实施，尚未执行本轮验收。

## 1. 已确认需求

- 前台语音 `voice_recall`、`remember`、`add_evidence` 的请求与结果进入 Chat 右侧 Activity 面板的 Activity 子组件。
- 请求参数复用文本 Chat 的展示，最多 500 字；一般工具结果复用 `display_output` 摘要（最多 1000 字）或成功／失败文案及真实错误原因。
- `voice_recall` 完整显示当前实际返回的记忆正文，每条保留既有 2000 字限制。后台普通 `recall` 完整显示其实际返回正文，不套用语音上限。无召回、格式异常与调用失败沿用文本逻辑。
- `remember`、`add_evidence` 的 `accepted` 不生成展示项；`done`、`failed` 复用现有方案；`unknown` 用中性“结果未确认”，正文“工具调用结果无法确认。”，有实际原因时追加“原因：{错误原因}”。不得按 `success=false` 将 unknown 判成失败。
- working 后台任务实际执行的工具请求／结果仅进入所属任务专属会话。不得扩大后台工具面，不将后台工具事件显示在 origin 会话或其他任务会话。
- 刷新、断线回放和会话切换时不得重复或串流；同一调用的请求和结果各有独立事件身份。Talk 关闭后异步结果仍通过持久消费展示。
- 本需求是工具事件到右侧组件的验证，不验证真实语义召回、硬件麦克风、扬声器、AEC、声学打断或其他 M6 能力。
- 浏览器页面操作／观察优先用内置浏览器；Sprint 4 WAV 注入明确允许 Playwright 调用外部可见 Chrome。注入只替换麦克风输入流，工具请求／结果仍由真实生产链路产生，无需用户口述。

## 2. 当前代码事实与复用设计

| 环节 | 当前事实 | 实施设计 |
|---|---|---|
| 后台工具面 | `background_preparation.py` 使用 default registry、`allowed_tool_names=None`；普通文本使用 full registry 和技能白名单，两者不完全一致。 | 按实际暴露且执行的后台工具接入通用事件处理，不复制工具清单或扩容。执行前策略拒绝未发 TOOL_START 的分支不在本次“实际执行的请求／结果”范围。 |
| 后台消息投影 | `execute_work` 已有 M5 Chat 消息持久投影，但 worker 未传 `on_event`。 | 复用 `on_event` 与行为事件存储，补接后台请求／结果。主聊天区消息卡与右侧 Activity 分别验收。 |
| 显示格式 | 文本格式化内嵌于 `_stream_chat`；前端 `ActivityEventRow` 消费 `title/detail/raw.kind`。 | 抽取共享格式器并做事件适配，不另造 recall 展示。未知工具名按通用结果展示。 |
| 状态 | 轻量工具权威回执有 state，但 TOOL_RESULT payload 未带 state。 | 持久化终态事件时携带权威 receipt.state，或从同一 command_id 的权威结果关联读取；选择一种实现并固定契约，不能猜测。 |
| 会话与回放 | `behavior_events` 已有 session、task、call 与各 stream 游标查询。 | 为选中 Chat 会话提供工具 Activity 增量读取；后台绑定 task_session_id，前台轻量事件绑定 origin。复用查询，不复用仅面向 origin 的任务列表事件流作为后台工具流。 |
| 去重 | 前台随机日志 ID 与单纯 append 无法覆盖持久回放。 | 使用持久 event_id 作为日志 ID；请求与结果分别去重；游标按 stream 保存。切会话取消旧订阅并检查会话身份。accepted 即使隐藏，也推进消费游标。 |

拟新增的共享模块与 API/前端适配由 planner 依据当前代码细化；预计不新增 SQL，复用行为事件 JSON payload。若实施发现 schema／迁移权威与本设计不符，停止相关写入并汇报后再调整。
