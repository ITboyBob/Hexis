## 1. 设计结论

### 1.1 主选方案

在现有16kHz PCM采集链后增加单线程模型Worker，以Silero v6提供人声概率；有效输入确认与目标响应打断分别判定，候选音频先留在本地，确认打断后复用现有本地停播、云端取消和迟到音频隔离机制。

### 1.2 选择理由

- 复用现有麦克风、AudioWorklet和重采样，保持M5采音暂停、恢复和会话身份一致。
- 使用人声概率替代响度作为主要证据，保留低音量人声的检测机会。
- 普通确认与高置信快速确认分开，避免把参考实现的固定8/10帧规则直接当成短中文指令的最终门槛。
- 确认前继续播放，拒绝候选不产生云端输入副作用。
- 资源随UI构建交付，运行实例不依赖个人缓存或模型CDN。

### 1.3 当前状态

已获取vad-web 0.0.31和onnxruntime-web 1.22.0原始npm包，校验registry完整性，并提取v6、v5对照模型与同版本JS、MJS、WASM资源。已在Node v24.18.0单线程WASM中加载两款模型并进行全零输入推理，核实输入输出名称、有效概率与循环状态形状。未安装仓库依赖、未修改产品代码，未运行浏览器、Next构建、语音识别效果或真实Talk验收。

## 2. 背景、目标与约束

### 2.1 当前情况

### 2.2 目标

纯噪音候选不直接打断回答；用户插话可确认并停止对应输出；短指令和轻声纳入独立验证；旧模型结果及旧打断命令不影响新会话或新响应。用户多次测试已排除扬声器输出为当前问题的声音源，本设计以环境非人声噪音为主要处理对象。

### 2.3 约束

人工验收由用户判断体验，不设置成功率、P95或固定次数门槛。代理验收采用逐场景断言和事件证据，数值统计用于诊断。凭据留在环境；真实云端测试使用显式配置与隔离测试数据库。模型失效不得静默退回旧RMS自动打断。原始下载包、一次性证据留在缓存；正式运行资源在实施阶段随产品构建交付。

## 5. 模块设计与选择

### 5.1 音频与模型适配

沿用已有重采样后的PCM，按512采样帧组织推理；模型输入为前64采样上下文与本帧拼接，形状为[1,576]，循环状态为[2,1,128]。PCM运输、哈希和原始时钟始终基于实际采集样本；模型上下文及测试补零不得进入发送音频。推理保留未满帧尾部，不用静默丢尾的方式完成短指令。推理结束结果与原始帧位置、采集代次关联。

### 5.2 Worker与生命周期

采用独立Module Worker，ORT numThreads=1、proxy=false、executionProviders=[wasm]。每个Talk媒体会话拥有一个Worker，模型ready后开启正式采集。Worker串行处理、输入队列有界；超时、过期批次和损坏状态必须显式报告，不在不完整模型历史上继续确认打断。暂停立即使旧代次失效，重置候选、模型状态和未满帧尾部；恢复等待重置确认；关闭销毁Worker。先保持现有“出现不可恢复采集故障则停止Talk、展示错误、由用户重试”的恢复方式。

### 5.3 两层确认与初始参数

状态依次为“安静→人声候选→有效输入”，打断门控另行跟踪“无目标→候选目标→确认目标→已处理”。候选和有效输入期间均可收集音频，只有确认目标后才停播。音量记录为诊断信息，不沿用固定RMS下限作为轻声的否决条件。

| 参数 | 初始设计值 | 状态 |
|---|---|---|
| 推理帧 | 512采样，16kHz，32ms | 已核实模型接口 |
| 模型上下文 | 64采样 | 已核实封装与加载 |
| pre-roll | 240ms | 继承现有参数 |
| 结束静音 | 520ms | 继承现有参数，兼容效果待测试 |
| 收音确认 | 最近3帧至少2帧概率≥0.60 | 调参起点，未验证识别效果 |
| 普通打断确认 | 最近6帧至少5帧概率≥0.80，当前帧满足门槛 | 调参起点，未验证识别效果 |
| 高置信快速确认 | 最近4帧至少3帧概率≥0.95，当前帧满足门槛 | 调参起点，用于覆盖短发声，未验证识别效果 |
| Worker输入积压预算 | 256ms音频 | 故障检测初值，非体验验收门槛 |
| 候选PCM缓存上限 | 1000ms音频 | 有界缓存初值，超限拒绝候选并记诊断 |
| 模型初始化超时 | 30秒 | 故障处理初值，非体验验收门槛 |

高置信快速通道判断声学证据，不识别“停”的字义；任何足够高置信的短人声都可能满足该通道。参数由真实模型调参集验证，再冻结独立验收配置；不能将初值当作已验证最优值。当前和历史参考值均保留来源，后续变更要更新配置版本。

### 5.4 候选缓存与输入区间

未确认候选不发送audio_chunk或barge_in，AI继续播放。确认有效人声后，发送从明确pre-roll起点开始的原始PCM，按原顺序持续传输。拒绝候选不形成独立输入，也不留下未声明的云端buffer。pre-roll可以包含最近的安静或噪音样本，但必须作为声明区间的一部分进入实际PCM及哈希。后续句子的区间仍受既有不重叠、连续帧和SHA256约束。

### 5.5 目标响应和并发取消

新增目标明确的barge_in_confirmed消息。API创建会话的`RealtimeSessionResponse`与WebSocket `ready`均携带同一个必需`barge_in_capability`对象：`supported`、C7 `configuration_id`、C7 `maximum_receipt_prefix_items`；ready保留现有schema_version/session_id/media_session_id/producer_seq/cloud_session_id/instructions_hash envelope，不把该能力字段复制到C1或客户端默认配置，也不把C7服务端的近期索引数量、保留时间或收尾超时复制到前端。API在创建云会话前读取并校验C7，将不可变能力快照绑定该media session；REST响应和WS ready必须从此快照生成。客户端严格解析REST描述，WS ready须在session/media身份及supported/configuration_id/maximum_receipt_prefix_items上逐项一致；缺项、错配、false或重复ready改值均不得开启新gate。supported只在服务端目标确认/前缀协调/持久化能力实际就绪后声明true。旧control消息不承载新门控的确认结果。

`barge_in_confirmed`复用schema_version/session_id/media_session_id/producer_seq envelope，另带`command_id`、`capture_instance_id`、`response_id`、`output_epoch`、`playback_id`、`local_playback_state`（`started`/`not_started`）和`receipt_prefix`。prefix项沿用现有HTTP `PlaybackEventRequest`字段及动作语义，不构造近似播放事实；`turn_id`只可出现在真实回执项，不重复放在确认顶层。started必须能够由服务端已有真实回执与prefix共同证明匹配目标的open及terminal interrupt；not_started只接受空prefix，并要求客户端先隔离该目标迟到音频且服务端确认无冲突open。prefix必须保持原始JSON请求的字段出现状态、值/类型、身份与producer_seq；服务端严格校验后保留原始prefix快照，避免Pydantic可选字段默认值或兼容转换改写；连续、有界、不得合成audible。

prefix项是HTTP `/api/voice/playback` body本身，不再包第二层schema/type envelope：

| 字段 | 形状 |
|---|---|
| `action` | 必需：`open`、`audible`、`progress`、`end`、`interrupt`之一 |
| `session_id` | 必需UUID |
| `response_id`、`playback_id`、`media_session_id` | 必需非空字符串，最大200字符 |
| `producer_seq`、`output_epoch` | 必需非负整数；回执序号按播放器实例递增 |
| `turn_id` | 可选UUID或null；无事实时真实emitter省略字段 |
| `start_ms`、`audible_ms`、`played_ms`、`interval_ms` | 可选非负整数或null |
| `phase` | 可选1–40字符字符串或null |
| `scope` | 可选`complete`、`partial`、`unplayed`、`unknown`之一或null |
| `reason` | 可选1–120字符字符串或null |

动作必需字段沿用现有HTTP校验：open需要`start_ms`，audible需要`audible_ms`，progress需要`played_ms/interval_ms/phase`，end需要`scope/played_ms`，interrupt需要`played_ms/reason`。prefix项及confirm外层均拒绝未知字段；服务端仍以C7运行时值检查prefix项数，不复制C7到C1。

命令幂等指纹包含完整session/media/command/capture/response/playback/epoch/local state/prefix语义，但排除外层WS `producer_seq`；同command_id相同语义内容以当前新的外层序号回读缓存结果，不重复持久化或取消；同ID不同语义内容拒绝。外层WS client producer序号、服务端producer序号、播放器回执producer序号是三个独立序号域，不能混用。

`barge_in_result`沿用服务端schema_version/session_id/media_session_id/producer_seq envelope，并回显command_id、capture_instance_id、response_id、output_epoch、playback_id及`status`。status仅为`accepted`、`playback_only`、`stale_target`或`unknown`：accepted表示命令已完成目标预留/隔离、必要回执持久化且必要cancel命令已写入，不代表provider终态；playback_only表示目标生成已终态、真实本地停止事实已协调且不需对无活动生成发cancel；stale_target表示旧目标不可操作且未影响新输出；unknown表示有界恢复后仍无法确定所需协调/持久化/provider写入结果，须关闭媒体并提示重开。结构、身份与prefix校验错误沿用error/HTTP 409/422，不伪装成result status。旧目标的confirmed命令不取消或释放新目标。

候选打断窗口绑定媒体会话、采集代次和前景响应身份。生成中、尚未audible时可由现有voice_model_call_started事件取得输出身份；已播放时由audio_chunk及本地播放器身份交叉核对。generation完成不等于播放完成，不能据此立即清除目标。响应切换后重建证据窗口；此前采集或推理结果不得用于确认新目标，持续插话须使用切换后的新证据重新确认。

确认后本地仅停止匹配的播放器并隔离该响应的迟到音频，向服务端发送同一目标；服务端校验capture状态和活动claim后才取消。相同command_id按身份幂等处理，不同负载复用同一ID拒绝；过期目标明确返回stale_target，不取消新的活动输出。

目标检查、标记失效与向云端写入取消必须与新响应创建的前景命令临界区协调，不能检查A后因并发切换而取消B。使用短时输出控制互斥，只覆盖目标校验及云端命令写入；不得持锁等待生成完成或播放终态，以免取消被阻塞。既有generation_done与playback_finished双终态释放规则继续保留。服务端确认返回barge_in_result，供关联证据及错误展示使用。

### 5.7 验收分层

代理验收需要逐场景通过条件，取消之前建议的统一95%成功率和P95≤500ms发布门槛。每个用例必须记录实际断言与失败原因；延迟和概率用于排查及比较，不用统计平均值掩盖单例失败。测试超时仅用于识别挂起，不等同于用户体验合格线。

| 场景 | 代理通过条件 | 证据 |
|---|---|---|
| 已audible输出期间纯噪音 | 不新增目标打断命令；播放不因候选被清空 | 注入游标、同一response/epoch、播放回执及状态 |
| 已audible输出期间有效人声 | 对匹配目标只产生一次确认、本地interrupt及取消；下一轮恢复 | command_id、目标身份、新增控制和终态 |
| 生成中但未audible | 明确取消对应生成，不误称已发生可听停播 | model_call_started身份、服务端取消结果 |
| 短指令与轻声 | 各标注用例均有独立识别、确认和首音节保留断言 | 真实模型概率、PCM区间、实际转写及播放事件 |
| 拒绝候选后正常一句 | 无未声明输入残留，实际PCM、区间和hash一致 | 运输校验、云端commit/final |
| 暂停、恢复、关闭和响应切换 | 旧模型结果或旧命令不打断新身份 | 采集代次、目标响应、状态日志 |

### 5.9 Architect首轮审查补充的确定边界

以下是根据当前代码审查补充的设计。其实现状态随执行推进单独标注，不能把计划边界误写成已完成能力。

**双ready门禁与分阶段超时。** C5现有`timeout`（30秒）用于API侧provider `connect/session_ready`阶段：到期关闭该session并从registry移除，不启动receiver或返回半成品媒体会话。RealtimeSessionResponse与WS ready从同一个经校验并绑定media session的C7能力快照产生。C1新增`readiness.server_ready_timeout_ms`（30000ms工程初值），从成功解析REST会话描述、准备创建WebSocket时启动，覆盖WS open到匹配ready；WS ready可早于open事件回调，监听器须预先安装。VoiceRealtimeClient.open严格比较REST/WS二者的session/media及整个barge_in_capability，再等待匹配服务端ready。C1既有`worker.initialization_timeout_ms`继续只界定模型初始化预算，不改称整个Talk打开总预算；worker ready与server ready都完成后采集控制器才能capture_open和发送PCM。C5 provider启动、C1 WS ready、C1 Worker初始化、C7 cancel settlement是四个独立预算，不能互相代用；REST描述到达前的DB操作不由C1 WS预算伪称受限。各阶段close/失败撤销本阶段等待。恢复仍需服务端capture_resumed及本地模型reset确认，不能用其中一个替代另一个。

**完整概率状态。** Int16采样用除以32768转换为Float32，模型sr张量为16kHz int64，原始Int16字节不变。active维持阈值初值为0.45；当前模型帧概率≥0.45清零静音计数，否则按该帧实际采样长度累计，首次达到520ms后结束，不再使用旧RMS作为active保持条件。32ms模型帧带来的判定粒度需如实回归，不能声称新的结束时刻与旧实现逐毫秒相同。未确认候选在最近3个已判定帧全部低于0.60或达到缓存上限时拒绝；清候选/门控证据，保留独立pre-roll，不重置持续检测的模型上下文。已确认输入不会因未满足打断门槛被丢弃；其正式转写与回答仍按现有输入授权及输出空闲顺序处理，原输出继续至自然结束，且不伪造interrupt。

**已判定水位。** Worker结果按采集代次与frame区间顺序消化。只允许已判定的原始PCM前缀进入正式发包；末尾未满模型帧、未返回推理和下一句样本留在有界raw缓冲。识别到句末时先按对应水位关闭本句并发送其hash，再处理后续样本；原始连续样本、上下文及分句区间分别记账。过期结果、缺口和超限走明确错误/恢复，不靠跳样本继续输入。

**播放事实协调方案。** 选择在目标WS确认中携带本地播放器已经实际发出的、尚未完成协调的回执前缀，而不是等待HTTP全部成功才停播。仍先即时停止匹配的本地播放器；从其真实emit记录截取open/audible/progress/interrupt等原始请求，保留原身份、producer_seq和内容，连同playback_id及local_playback_state发送。started必须携带足以证明open与terminal interrupt的前缀；not_started只在该目标确实未发open时使用，并且客户端已将该目标迟到音频隔离。不得合成audible或用已收到音频块替代播放事实。前缀有界（初值最多256项）；无法完整提供时错误可见并停止当前Talk，不能省略关键回执后继续。

服务端处理顺序固定为：完整校验目标及前缀→短时输出锁中登记command和取消中隔离状态、保留目标→锁外协调回执并持久化→短锁内重验同一保留目标、发送必要cloud cancel→记录结果及允许双终态释放。取消中立即隔离旧音频和未开始的旧voice工具授权，生成终态/HTTP终态可记录但不得释放保留目标，新的输出不得越过此状态启动。已提交的任务及已经发生的工具副作用保留，禁止重放或假称回滚。生成已结束而播放仍在进行时，interrupt不先释放目标，命令可以完成为playback_only而不是误报stale。收尾失败则隔离仍生效，进入有界unknown/关闭媒体恢复路径，不能为了继续下一轮而悄悄解除目标保留。

WS与HTTP的播放事实交给同一响应级校验、幂等及历史记录协调器；完整校验包含身份/序号/范围，不能因取消中就拒绝该命令已校验的真实回执前缀。相同序号相同内容的重复请求进入相同处理记录，相同序号不同内容仍拒绝。协调器串行执行同一响应回执，并为每项明确区分已验证/待持久化/已持久化，重复等待已有处理或恢复待持久化步骤，不能仅按内存receipts存在就返回最终成功。复用PlaybackHistory稳定event_id及既有行为事件数据库幂等，以相同身份、序号和请求内容重试；数据库写失败、已提交但响应丢失都不丢掉待确认状态。只有必要播放事实持久化完成后才确认其历史完成并触发voice_turn_completion，完成事件仍幂等且只记录一次。

短时输出锁只用于目标保留、前景命令写入和保留解除，不等待HTTP、数据库、回执协调锁、生成完成或播放终态。回执协调阶段不持输出锁；如需更新目标内存状态则短暂取得输出锁，其他路径不能持输出锁反向等待回执协调，从而固定锁顺序并避免死锁。释放检查显式考虑pending command、双终态及必要历史持久化状态。

**执行状态（S3-S4截至2026-10-08）：**双ready门禁、C5 provider启动deadline、独立C1 server-ready预算、C7能力snapshot及S3.2严格消息契约已落地。S3.3已落地响应create前claim/playback/input/queue映射预留、失败回收，以及统一短时命令锁协调create/cancel/release；锁外等待idle和终态，排队中的旧取消在拿锁后若目标已切换则返回stale，不触碰新响应。S3.4/S3.5已落地播放器原始回执ACK水位、WS确认、HTTP/WS串行持久化、命令语义幂等、近期终态精确回读及有界unknown关闭；专属DB/Vitest定向测试通过。S4.1概率gate与S4.2候选PCM已接线：只有输入gate确认才上传；只有独立打断gate确认且采样时target仍匹配才本地停播并发confirmed。S4.3支持从`voice_model_call_started`绑定未播放响应目标，S4.4等Worker和WS ready后才capture_open，并等待server suspend/resume及Worker reset双确认。C1声学阈值仍`unvalidated`；没有云端真人取消或Talk端到端验收证据。
